Repository Sync — Git Workflow

Overview

Repository (File ▸ Open Repository, Alt+5) provides a simplified Git workflow for keeping a shared pattern or workspace library in sync with its Git remote. The left Settings pane holds the folder, Auto sync, and workflow cards; the right pane shows Git output. In a narrow window the Settings pane folds into a drawer with a Show/Hide button.

Setup

  1. Select the repository folder: type its path or choose Browse… and pick the repository's root folder.
  2. The line under the path says whether the folder is ready, or exactly what is wrong: the folder is not found, the path is a file, you have no permission to open it, or it is not a Git repository. When the folder is inside a repository, the message names the repository root to choose instead.

Workflow Cards

1 Pull from remote

Pull fetches and merges updates from the configured remote. Follow with review/commit, then push the commit to the remote.

2 Review and commit

Commit shows the changed files for review, then stages all changes and commits them with the message above (default "Update project files"). If Git has no author name or email for the repository, you are asked for them first.

3 Push to remote

Push is the final primary action: sends the committed changes to the remote. The branch needs a configured upstream remote; if it has none, Git reports the missing upstream in the step status and Git output.

Step results

Each card shows its last result. A failed step names the cause and quotes the key line from Git — for example authentication failed, no remote configured, no upstream branch, conflicting changes, the remote has newer commits, a network error, a timeout (each Git command gets 30 seconds), or cancelled — followed by "Details in Git output".

Destructive actions

Reset to Remote… is separated from the normal Pull → Commit → Push flow. It discards local tracked and untracked changes to match the remote tracking branch, and requires confirmation.

Auto Sync

Turn on Auto sync this repository (also in File ▸ Auto Sync Repository and Settings) to keep the selected folder and its remote in step without pressing any buttons:

  • Local changes: edited or newly added files are committed a few seconds after saving stops, then pushed. Remote commits are pulled in first, so the push is not rejected.
  • Remote changes: checked every minute and pulled whenever no local edits are waiting to be committed.
  • Conflicts: if the same file changed on both sides, Auto sync undoes the attempted merge, leaves your files untouched, and pauses. Use Pull to resolve it, then turn Auto sync back on.

The line under the toggle shows the current state:

  • Off — Auto sync is turned off.
  • On — waiting for edits — watching for changes; after a check it adds the time, such as "up to date at 14:02".
  • Syncing… — a sync is running.
  • On — synced at 14:02 (pulled 1, pushed 0) — the last sync's result and time.
  • Problem at 14:02 — … or Paused — … — the reason syncing failed or stopped; a paused sync resumes when you turn it back on.

Every sync that commits, pulls, or pushes — and every new failure or conflict — also appears in Git output under an "Auto sync" heading; routine checks that find nothing to do are left out. The branch must already have a remote branch; push it once with Push first.

Secondary Actions

  • Status: show the current branch and changed files in Git output.
  • Cancel: stop the pull, commit, or push in progress.
  • Show in Finder (Show in Explorer / Show in Files on other systems): open the repository folder in your file manager.

Git Output

The right panel shows the output of every Git command run from this page or by Auto sync: each command is listed as $ git … followed by what Git printed, with errors highlighted. It is a command log, not a commit history. Clear empties it.

Settings Integration

The repository folder path is persisted in your settings and remembered between sessions. You can configure the default repo directory in Settings.
